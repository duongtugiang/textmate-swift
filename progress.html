b2ef81a — feat(core): bundles framework (4.S6) + bundle suites green (4.T3)

2026-08-21
Why: 4.S6/4.T3 — bundles are the last dependency-ordered piece of the grammar stack: they make arbitrary grammars loadable (the built-in one was hard-coded) and absorb the dispositioned `regexp` utility suites (glob/format-string/indent follow).
What: three new TextCore modules — TextPlist (old-style ASCII plist parser for .tmLanguage/.tmBundle), TextFormatString (variable expansion: $VAR, ${VAR}, fallback :…, condition :+/:?…:…, and /pattern/format/options substitution with nested capture backrefs and \U case changes), and TextBundles (BundleItem/BundleIndex: field+scope-ranked query with exact kItemType* bitmasks, scope_variables with per-pair accumulation + v1 shadowing, required-bundle support paths, missing_requirement). App side: Bundles ▸ Load Grammar… menu loads any .tmLanguage or .tmBundle (first Syntaxes/*.tmLanguage) and swaps the document grammar. t_query (4) + t_requirements (1) ported verbatim; 107 tests green; issues #33/#36 closed.
How: four real bugs surfaced by the port: (1) old-style plists treat single-quoted strings as literal — the parser was unescaping \b to b, silently breaking every grammar pattern; (2) scopeSelector?.doesMatch ?? 1 turned a non-match (nil) into rank 1, making every scoped item match every scope; (3) scope_variables must expand each pair against the accumulating result (C++ tmp << res) and walk the shadow stack most-specific-first (riterate); (4) the required-bundle query matches by the item’s bundle_uuid(), which is a top-level bundle’s own uuid. Also caught a SwiftPM quirk: swift build --target compiles but never links an executable product — use swift run.
